# 工作区 SSH 隧道

API、Redis 和网络 SQL 数据库可复用当前工作区已保存的 SSH 连接。API、Redis、SQL 和 SSH 终端还可选择当前工作区已连接的堡垒机临时会话。用户填写最终服务的域名和端口，由跳板解析内网域名。

## 交互

- DataGrip 允许在数据源上选已有 SSH 配置，DBeaver 将 SSH 设为数据源的网络配置并允许复用。Unfour 采用已有连接选择器，SSH 主机、私钥、密码与主机密钥信任仍在 SSH 模块维护。[DataGrip](https://www.jetbrains.com/help/datagrip/configuring-ssh-and-ssl.html) · [DBeaver](https://dbeaver.com/docs/dbeaver/SSH-Configuration/)
- API 发送区展示实际路由。请求默认继承环境，也可选直连或指定 SSH。环境可设置本机默认路由。修改请求覆盖后，发送按草稿执行，保存后同设备上的 Flow 复用它。发送时校验界面显示的环境与路由，遇到变化重新加载后再发送。一个环境的变量和路由须在同一次执行中一致。
- Redis 的创建和编辑表单提供直连或 SSH。目标始终是 Redis 服务，SSH 是访问途径。测试连接使用表单中的实际路由。切换途径影响凭据复用与本机写入授权。
- PostgreSQL、openGauss 和 MySQL 的连接表单可选择现有 SSH 跳板。测试、目录、查询、脚本、编辑和导出都走相同配置。修改已保存的跳板后，在数据库连接中确认新版本，再保存。SQLite 使用本机文件。
- 临时会话只在当前窗口内被选用。API 的选择作用于请求标签页，数据库和 SSH 的选择作用于所选连接。关闭堡垒机标签或工作区会中断已有转发。下次使用须重新选择可用会话。SSH 终端仍需校验目标主机的指纹并使用目标自己的凭据。
- SSH 引用失效、主机密钥未确认/已改变、认证失败和禁止端口转发时显示对应错误。首次信任通过现有 SSH 入口完成。停止请求会释放本次使用的资源。已选择 SSH 的操作发生错误即停止。

## 执行边界

共享的是工作区的 SSH 连接定义、凭据与主机密钥校验，以及在 SSH 服务器上打开 TCP 通道的实现。通道按操作持有，首版不做跨操作的长连接池。SQLx 在每次取得新的物理连接时向选中的跳板打开通道，TLS、数据库认证和协议探测继续使用目标数据库的参数。

- CommandBus 按工作区校验来源、请求/环境和 SSH 连接。HTTP 编辑器、保存请求重放和 Flow 进入同一条传输路径。Flow 固定本次选定的资源和网络路由，配置变化时终止该步骤。
- SSH 引擎用 direct-tcpip 连接目标。Redis 直接在通道上运行 TLS、认证、SELECT 和现有命令。HTTP 引擎通过仅监听回环地址、持有临时认证的 SOCKS5 代理使用同一 SSH 通道能力，重定向也保留相同路由。目标 URL、Host、SNI 和证书校验均保持原样。
- API 选择直连时继续使用既有 HTTP 客户端及其系统代理行为。指定 SSH 时对这次请求显式使用隧道。Flow 选择“仅工作区”时使用工作区变量，请求继承环境的路由按直连处理；显式请求覆盖仍生效。
- API 的环境默认与请求覆盖是本机网络偏好，按 workspace_id 和资源储存；共享请求到其他设备时，使用该设备的网络偏好。短期代理端口、代理密码、私钥及会话不进入请求定义、历史和 Cloud Sync。
- 同一设备上的窗口通过工作区变更通知刷新路由。保存时核对编辑前的设置。如果另一窗口已改变该路由，用户需要重新核对后再保存。
