# 堡垒机外部连接：内部基础契约

v0.15.0 的配置方式、执行模式与交付范围见
[用户指南](../user/USER_GUIDE.md#temporary-bastion-sessions-v0150)及
[发布说明](../release/v0.15.0-release-notes.md)。下方日期化条目保留各阶段的演进记录。

外部 SSH 启动会在工作区布局就绪后打开 SSH 模块。只有一个可用工作区时，界面将请求认领到该工作区并开始连接。多个工作区时，由用户在目标工作区确认。两条路径共用主机指纹校验。临时终端显示期间保留普通 SSH 连接树，选择已保存的连接可以返回普通连接视图。

## 已登录终端的 SSH Task

用户在目标机的空闲 POSIX shell 中确认本次操作。Task 和终端 curl 共用独占输入租约。
原生终端读取器持续跟踪已知的独立登录提示。即使界面读走了输出，收到 READY 前的每次写入仍检查该状态。
已识别提示时，首次写入会被拦截，未写过的终端可以继续手工登录。检查与 SSH 写入之间，
远端仍可能切换到登录菜单、前台程序或未完成的输入行，此时固定引导行有可能被它们读到。
界面轮询、屏幕文字和 SSH 已连接状态都不能证明目标身份或 shell 空闲。

首次写入只有固定引导行。收到启动帧才发送本次随机会话标识，收到匹配的 `READY` 和
操作 `ACCEPT` 才开始发送编码正文。等待启动帧及 `READY` 时也会核对原生读取器的状态；
登录提示的前半段在申请租约前已被界面读走时，仍可识别随后到达的完整提示。
若此时取消、超时或识别到提示，已写入的终端只被动等待本次恢复标记。没有关联
`READY` 就不会发送 Ctrl-C 或 `Q`。恢复未确认的终端进入隔离，须从堡垒机重新登录。

命令按最多 48 个原始字节分段。每段收到匹配本步骤、序号、长度和全部内容的确认后，
驱动才继续发送。子 shell 校验结束行中的总段数和总长度后才执行。输入未确认会停止
整个 Task，即使步骤允许出错后继续。结束行可能已送达但结果丢失时，报告结果未知。
两个 Task 执行模式都在执行步骤正文的子 shell 内切换工作目录。切换失败立即以该
非零状态结束本步骤。原始输出中孤立的 RS 字节保留为数据，后续匹配的 STATUS 和 END
共同确认退出结果。
临时目标目前仅用于用户显式选择的单个 Task 和 API 请求，Flow 暂缓接入。

## 2026-11-17 临时会话保活与重新协商

临时 SSH 使用独立的 60 秒协议保活与 3 次未回应容忍参数，保留握手/认证各 30 秒、
PTY 启动 15 秒的阶段上限。心跳由 Rust 传输维护，不依赖终端页面可见性，不发送
PTY 字符串、回车或业务命令，也不重新认证。VDI 桌面断开但宿主进程继续运行时，
保活仍可运行；虚拟机暂停、断网和堡垒机强制结束会话仍不能由客户端保活保证恢复。

保留正常 SSH 密钥重新协商，重新协商的主机密钥必须再次通过校验并匹配原会话指纹。
为此对锁定版本 russh 的主机密钥回调做局部修正，来源和补丁说明见
[russh 本地补丁](../../vendor/russh/UNFOUR_PATCH.md)。
不得通过延长或禁用 rekey、跳过主机密钥校验来维持连接。断开原因仅以固定、脱敏
代码展示，不暴露远端描述；断开仍需从堡垒机重新发起，不自动重放票据或任务。

本轮实现、验证及主程序交付见 [保活现场记录](../testing/bastion-keepalive-2026-11-17.md)。

## 2026-11-18 API 复用终端 curl（当前契约）

V4 减少引导和上传确认的往返。快速传输仅用于通过同一空闲 shell 的终端 curl 能力
检测、且配置与编码帧均在检测上限内的请求。每次尝试快速传输前重新核对 shell 上下文。
每次发送仍检查所需的 curl 选项。快速传输使用 SHA-256 校验输入完整性。
资格失效或条件不足时使用保守传输。
耗时数据、检测条件和回退边界见
[终端 curl 性能与验收](../testing/bastion-curl-latency-2026-11-18.md)。

curl 7.29 兼容补充：普通正文使用 `data-binary` 字面值；首字节为 `@` 时先严格检查
`data-raw`，不支持则在 HTTP 发送前返回 `SSH_TERMINAL_HTTP_CURL_BODY_UNSUPPORTED`，
禁止把正文解释成远端文件路径。检测与每次 API 发送共享 core 中的固定 CLI 选项契约，
不再用旧版可忽略未知选项的 config 退出码作为支持依据。敏感值仍只进入 stdin 配置。
现代 curl 显式指定 HTTP/1.1。明确识别的 7.29–7.32 且未宣称 HTTP2/HTTP3 能力时使用默认 HTTP/1.1，
其余构建必须接受显式选项。远端超时向上取整至整数秒，本地毫秒期限不变。
正文上限为 10 MiB。HEAD 收取响应头和空正文，允许资源声明更大的 Content-Length。
对于 chunked 响应，按 curl 报告的下载字节数取解码后的正文。如 curl 同时输出
trailer，逐行校验字段格式。所有头块（含前置 1xx）和 trailer 合计限 128 KiB，
终端总输出另有上限。[本轮缺陷验收记录](../testing/bastion-review-2026-11-18.md)
普通 JSON 在业务发送前执行一次严格 CLI 预检并从同次输出选择 HTTP 版本。
响应“耗时”视图保留终端操作总耗时，并显示准备、输入、确认次数与等待、远端执行与回传、
恢复、curl 至首字节及 HTTP 总耗时。输入确认包含结束确认，两个 curl 指标均从传输开始累计。
耗时字段内仅含数值，随本次响应返回。真实旧版复现与验证见 [curl 7.29 兼容记录](../testing/bastion-curl-729-compatibility-2026-11-17.md)。

阶段诊断与恢复补充：raw curl 预检在关联子 shell 后完成，明确工具失败只被动等待
恢复；未知启动状态不盲发 Ctrl+C。超时保留固定阶段，恢复确认缺失仍锁定输入。
terminal curl 的 0/空超时采用专用 30 秒默认，显式正数保留；不改变直连/TCP 契约。
现场记录见 [curl 阶段诊断与恢复](../testing/bastion-curl-recovery-2026-11-17.md)。

V3 在子终端用固定样本验证 base64 解码的退出码与输出。通过时每行传输至多 180 个原始字节，
仅支持编码的环境继续用原有八进制，每行至多 48 个原始字节。两种方式线上均至多 242 字节，
仅允许一行待确认。逐行确认操作标识、序号、编码长度和完整编码内容，结束行携带
总行数和总长度，远端校验后才解码执行，本地确认后才进入 BEGIN 等待。子 tty 显式
设置 Ctrl+C，退出恢复原配置。最终输入确认丢失仍可能已执行，不能自动重发。
兼容性对照及现场步骤见 [输入确认修复](../testing/bastion-curl-input-confirmation-2026-11-17.md)。

终端传输与 curl 检测分别报告：`transport` 使用约 1 KB 固定输入、二进制输出和预期退出码
23，不调用 curl、不访问 HTTP、不安装程序。`curl` 在同一个独占 lease 下先完成传输往返和
恢复，再独立检查 curl 工具与选项及恢复；任一前置失败或取消都不继续。报告保留各阶段固定
结果码，不包含协议帧或远端正文。输入确认回传编码内容仅由内存中的独占驱动消费，不输出
到终端、日志或脱敏报告。V3 READY 明确版本、240 字节编码载荷上限及所选编码，能力不符拒绝发送。
引导成功后的临时子 shell 规范化 CR/LF 并忽略 CRLF 的空行，退出时恢复完整 tty 设置。BEGIN 由执行子
shell 在安装信号处理后发送，避免收到 BEGIN 时执行子进程尚未创建；取消仍不保证远端副作用
撤销，恢复未确认继续隔离输入、不自动重放 POST。集中验证与限制见
[传输分层验证](../testing/bastion-transport-curl-separation-2026-11-17.md)。

API 可显式选择 `terminalCurl`，默认兼容原 `tcp`。当前工作区临时终端在前置脚本
运行前被独占，API/Task/终端检测共享输入互斥与恢复隔离。HTTP 引擎生成有界配置并
解析响应，SSH 引擎负责原始字节编码传输，CommandBus 编排；Tauri 不包含领域逻辑。
不新开 exec 或 direct-tcpip，不自动回退与重试，不持久化临时目标。完整响应与终端
恢复结果分开处理。具体支持范围、安全边界和交付证据见
[终端 curl 现场记录](../testing/bastion-api-terminal-curl-2026-11-17.md)。

## 2026-11-17 已登录终端 Task

现场证据显示额外 exec 通道可能重新进入登录流程，不能把同一 SSH 传输等同于
父终端内已完成的资产登录。补充显式的 `terminal` 执行模式，原生 `exec` 为兼容默认；
禁止隐式回退、自动登录及任务重试。终端模式仅接受 command，独占父 PTY，经过
子 shell 握手后才传任务正文；结束需确认终端恢复。能力检测分别描述额外通道与
已登录终端，不声称自动核实目标资产身份。现场步骤及最终证据见
[终端 Task 现场记录](../testing/bastion-terminal-task-2026-11-17.md)。

## 2026-11-16 TCP 检测与临时目标 Task

本节更新下方早期阶段的“临时目标不提供 Task”限制。外部启动参数仍不能携带命令或
自动执行任务；用户在已连接会话上手动确认运行的单个 SSH Task 已接入，Flow 尚未接入。

API 使用 SSH TCP 转发时，失败结果可携带本次请求的 `httpRequestMayHaveBeenSent`。
SOCKS 协商和打开 SSH 通道不计入业务发送。代理在首批客户端数据被 SSH 流接受后才记录
“可能已发送”，并保留先前重定向跳的记录。若错误先于首写，代理禁止迟到的写入。
TLS 握手也可能产生首批字节。代理无法仅从加密流判定业务 HTTP 是否送达，界面保守提示结果未知。

- TCP 检测由用户填写目标主机/IP 与端口，只打开并关闭一个 `direct-tcpip` 通道，
  不发送 HTTP 或其他应用数据。目标由堡垒机一侧解析和连接；检测成功不代表 API
  的认证、路径、正文或 HTTP 响应成功。输入端点不进入结果报告或持久化记录。
- 通用转发失败拆为 `SSH_TUNNEL_FORWARD_PROHIBITED`、`SSH_TUNNEL_TARGET_CONNECT_FAILED`、
  `SSH_TUNNEL_CHANNEL_UNSUPPORTED`、`SSH_TUNNEL_RESOURCE_SHORTAGE`、
  `SSH_TUNNEL_TRANSPORT_CLOSED`、`SSH_TUNNEL_FORWARD_FAILED`；超时保留
  `SSH_TUNNEL_TIMEOUT`。分类依据 SSH 协议拒绝原因，不猜测服务器权限或透传原始错误。
- Task 保存仅要求任务名称及有效定义，不要求本地保存连接。运行对话框可以选择当前
  工作区的已连接临时节点，使用同一已认证 SSH 传输执行 command/upload/download，
  不再认证，也不经 PTY 模拟命令。任务修订、输入变量版本、秘密遮盖及执行 guard 仍校验。
- 定义可以正常保存；临时运行的目标、上下文、输出和结果只在内存保留。每个父会话
  最多一个运行中任务、四个运行记录，每份日志约 256 KiB；不会创建 SQLite run、日志/
  owner 文件、默认/最近连接绑定、运行活动或云同步。取消只关闭任务拥有的通道。
- Windows 主窗口在首次导航前关闭 WebView2 通用自动填充；运行参数输入也关闭
  HTML 自动填充。仅设置 HTML 属性不足以阻止 Edge 扩展字段历史保存，实包必须检查
  浏览器存储与应用数据库两个边界。
- 关闭父标签、离开工作区或退出应用清除所属结果并取消运行。断线后有限保留终态结果
  供查看，不能恢复目标或自动重跑；再次运行必须选择当前有效目标。

现场步骤及主程序交付证据见 [TCP/Task 验收记录](../testing/bastion-task-tcp-2026-11-16.md)。

## 2026-11-16 手动能力检测（A4 现场入口）

已连接的临时会话提供“能力检测”入口。启动本身仍只建立终端；只有用户确认当前为
获准测试的目标并手动运行后，才在同一已认证传输上追加检测通道。exec/channels/SFTP
检测不接受任意命令、路径或认证材料；TCP 仅接受显式主机与端口。不重新登录，
不重放启动票据，不建立持久 Task/Flow 绑定。

- `exec`：两个顺序 session 通道执行固定合成输出，分别核对 stdout、stderr 和
  原生 exit-status（0、23）。终端内手工执行命令不替代此结果。
- `channels`：同时打开两个额外 session 通道并分别执行固定命令；结果只证明本次
  连接可容纳终端加两个检测通道，不推断无限并发或连接生存期内的通道总数。
- `sftp`：另行确认后请求同一传输的 SFTP subsystem，在 `/tmp` 下独占创建随机
  `unfour-a4-` 文件，写入少量合成内容、读回核对并清理。仅删除本次成功创建的文件；
  断线或清理失败必须显示未确认，不能把检测取消等同于远端文件已清除。

CommandBus 和 Tauri 只暴露 scoped `start/get/cancel`；检测实现由 ssh-engine 拥有。
每个临时句柄同一时刻只运行一个检测，后台任务有界，取消仅停止检测；关闭父会话、
工作区或传输失效时停止所属检测。固定结果码不包含远端输出、原始错误、端点或账号。
检测记录只在内存保留；用户可手动复制脱敏报告，不自动写入 SQLite、活动记录或云同步。
断线后保留只读入口及最终报告（包括未确认清理的随机路径），直到显式关闭标签、
工作区或退出应用；仍受临时会话总数上限约束。断线状态不允许再启动检测。

本入口是现场取证工具，不表示客户环境已支持 exec/SFTP。独立 WinSCP/文件传输入口、
新的网页授权登录、同票据能否复用、授权到期和代理/helper 生命周期仍分别待现场记录。
完整步骤与本机验证证据见 [能力检测离线验收](../testing/bastion-capability-probe-2026-11-16.md)。

## 2026-11-16 交互优化（当前契约）

- 标签和转发来源选择器显示启动入口提供的节点名称，缺省使用连接地址；上下文显示
  实际 SSH 传输的 `host:port`。若 AccessClient 使用本地代理，此地址是代理端点，
  不推断为下游资产 IP。外部标题只作显示，不参与连接、认证或命令执行。
- 安全摘要新增内存字段 `displayName` / `endpoint`。标题排除含完整认证身份、密码或
  URI 的内容，清理控制/双向文本字符并限制为 160 字符加省略号。用户名、票据、密码、
  原始 URL/argv 仍不进入前端；显示 metadata 不持久化到 SQLite、历史或云同步。
- 临时 SSH 改为自动首次使用信任（TOFU），不再要求点击“仅本次信任”。已有工作区
  持久指纹仍必须匹配；首次指纹仅在内存记录，以工作区、大小写规范化主机名、端口
  为键，后续新启动复用该记录。指纹不符拒绝连接并返回固定错误码，不自动覆盖。
- 内存指纹最多 1024 个，满时拒绝新增端点而不淘汰旧指纹。关闭单个标签不清理指纹；
  关闭/离开工作区或应用退出后释放。重开工作区对未持久记录的端点重新执行 TOFU；
  本策略不提供跨重启的首次身份保证，也不表示堡垒机授权可以替代指纹匹配。
- 查库后再次确认所属句柄仍处于连接中；并发首次握手在同一锁内比较并记录指纹。
  传输建立上限改为 30 秒，认证 30 秒、PTY/shell 15 秒不变。旧 trust 命令仅为兼容
  保留，返回 `TEMPORARY_TRUST_STATE`，不能用它覆盖新策略的拒绝结果。

以下按日期保留的实现记录如有冲突，以本节为准。验证与交互回归见
[本轮测试记录](../testing/bastion-ux-review-2026-11-16.md)。

当前工作区已连接的堡垒机会话可供用户显式选择为转发来源。选中后，目标服务通过这次已认证的传输建立 `direct-tcpip` 通道，目标域名由堡垒机解析。普通 SSH 目标仍独立验证自己的主机指纹并使用自己的凭据认证。拒绝转发会结束本次操作。关闭父标签或工作区、父会话断开或重新协商密钥都会关闭所属转发；经临时会话建立的子终端断开后需由用户重新连接。

子终端的复制和手工重连沿用原会话的路由。子终端历史仅记录它曾依赖临时会话，父句柄只保存在内存。重启后必须重新选择父会话并建立新连接。桌面 SSH 任务同样可使用本窗口为目标选定的临时路由，任务的命令和文件传输在目标自己的 SSH 登录上执行。每个父会话容许 32 个尚未确认的转发请求；已取消的通道若收到迟到确认，会直接关闭。

## 2026-11-23 SecureCRT 参数兼容

升级后的 AccessClient 现场脱敏弹窗显示 13 个 argv，前两项为 `/S <session>`，
随后是原有 11 项 SecureCRT 参数。客户端具体版本和 `/S` 的内容尚未确认。
解析器支持带或不带该前缀的格式，也接受末尾一组只影响 SecureCRT 窗口外观的
`/TITLEBAR <title>`。这两个可选值须是非空白的有效 Unicode，禁止控制字符和 `|`，
并计入参数值合计 64 KiB 的限制。

Rust 丢弃这两个可选值。`/N` 提供 Unfour 标签，连接与认证字段取自显式的
`/SSH2`、`/P`、`/L`、`/PASSWORD`。仅提供 `/S`、追加未知参数或重复开关、
更换参数顺序的调用仍触发脱敏启动诊断。冷启动与已有实例的接收端使用同一解析器。

## 2026-11-16 SecureCRT 外层调用

用户通过客户 AccessClient 的 scrt 入口启动诊断包，脱敏报告确认 11 个 argv 的顺序：
`/T /N <label> /SSH2 <host> /P <port> /L <identity> /PASSWORD <credential>`。
当时只兼容这套固定顺序与参数数目。诊断器会规范化已知开关大小写，因此解析器接受
ASCII 大小写等价的斜杠开关，不声称已经观察到原始大小写。

host 为 ASCII 域名或标准 IPv4，port 为非零且无前导零的十进制 u16。字段均需非空、
有效 Unicode，不能含控制字符或单实例分隔符 `|`；字段合计最多 64 KiB，标签不能全空白。
用户名和凭据是独立 argv 中的字面值，不按 URL 解码、不裁剪、不拆票据，开关形状的
凭据也只作为值使用。标签校验后仅用于显示，连接只取 host/port/identity/credential。

两种入口共用原有 Rust 临时队列、工作区认领、主机信任、一次性认证和终端生命周期。
不新增保存连接、认证探测、自动重连或持久化授权。脚本、会话文件、额外开关、任意参数
重排、SFTP 和其他 SecureCRT 格式不在兼容范围内；拒绝时仍显示脱敏启动诊断。
实际 argv 结构已由现场确认；用户随后报告兼容包在现场登录成功。此结果不代表
exec/SFTP、凭据重用或后续部署能力已完成验收。
详见 [scrt 离线验收说明](../testing/bastion-scrt-launch-2026-11-16.md)。

## 2026-11-11 Windows 外层调用

Windows 桌面在 metadata CLI 之后、插件初始化之前校验已拆分的 argv。支持现场观察到的四个参数 `-url <SSH URL> -newtab <标签>`。适配器仅从 URL 构造 Rust 临时连接字段，标签校验后仅用于显示。Tauri 主实例在 setup 中接收冷启动请求，已有实例回调使用已准备的 CommandBus。每次真实进程调用分配一个 receipt，UI 就绪前请求沿用 Rust 队列的保留期。

Windows 更新器和应用重启只继承可执行文件名。启动参数中的堡垒机票据和 OAuth 回调由当次进程消费，安装器拉起的新进程按普通桌面启动。

当前单实例插件在 Windows 上以 `|` 拼接 argv，故发送前检查边界，主实例在接收时再次校验。错误只输出固定码。URL 的支持子集、复现步骤与 A4 待确认项见[Windows 离线测试说明](../testing/bastion-xshell-url-offline.md)。以下记录描述 PR #9 时的基础契约。

| 阶段／事件 | 当前行为 |
| --- | --- |
| 传输／主机握手 | 独立 30 秒上限；首次未知指纹按当前自动 TOFU 契约处理 |
| 认证 | 独立 30 秒上限 |
| 初次终端启动 | 建立一个 PTY shell，总限时 15 秒。只有用户随后选择转发时才会发起额外的目标 TCP 通道。 |
| 信任 | 首次握手比对工作区已有指纹，遇到变更即拒绝；未知指纹仅在工作区会话内存中 TOFU。每次重新协商再次校验主机密钥，并严格匹配原会话指纹；无法验证或指纹变化即拒绝。 |
| 取消／关闭标签 | 移除目标、取消等待、关闭已取得资源；迟到 transport/channel 不能恢复目标；输入/resize 上限 5 秒，关闭 channel/transport 各最多 2 秒 |

| 工作区切换／关闭 | 离开该工作区的 SSH 容器时关闭所属临时目标，永不迁移；未认领请求保留原 TTL；StrictMode 即时 readiness 重放不会误关闭 |
| 删除工作区 | CommandBus 删除后清理目标；workspace epoch 拒绝与关闭同时发生且仍在等待 DB 的迟到认领 |
| 应用退出 | 释放本进程资源，不结束 AccessClient-owned helper，不保存恢复记录 |

以上时限是本地资源上限，不能视为堡垒机授权有效期。单实例第二进程退出是否破坏代理仍未知。
实际冷／热启动接入与 Windows 打包验收不能由 typed 队列测试代替。

临时路径不调用普通保存连接、keychain、session/history、activity、Cloud Sync/outbox、

关闭即删除；断开后的 Rust 摘要／输出最多再保留 120 秒并独立定时清理。

新增直接依赖 serde 用于安全摘要、zeroize 用于秘密缓冲；tokio 从可选改为必需，

## A1 原始设计草案（历史上下文）

关联 [A1 #4](https://github.com/zyqzyq/Unfour/issues/4)、
[A2 #5](https://github.com/zyqzyq/Unfour/issues/5)、[A3 #6](https://github.com/zyqzyq/Unfour/issues/6)。
这是待真实末端语法补齐的设计约束，**尚未实现、不是 main 已有 API**。
[本机证据与缺口](../testing/bastion-accessclient-a1-2026-11-10.md) 是启用入口的门槛。

## 边界与所有权

```text
AccessClient 保持现有浏览器入口与授权/代理职责
  → desktop adapter 接收外部输入（Windows argv 边界保留，不经 shell 重拼）
  → CommandBus 校验工作区与受控动作
  → ssh-engine 临时请求/目标服务（Rust 内存）
  → 现有 SSH driver 与主机信任检查

ssh-terminal UI ← command-client ← 安全摘要与不透明句柄
```

`unfour-app` 负责冷/热启动投递与 UI readiness 的组合；不承载 SSH 业务状态。
`ssh-engine` 拥有待认领认证材料、临时目标、连接取消与生命周期。
`unfour-command-bus` 统一编排；Tauri/MCP 不复制域逻辑。
前端业务归 `packages/ssh-terminal`，共享契约归 `command-client`/`workspace-core`；
app-shell 只装配布局。新增 UI 文案必须使用共享 i18n。
本阶段不暴露 MCP 任意外部启动入口，不允许把启动输入转成 Task/Flow 或命令执行。

## 最小内部请求（语义草案，不是序列化结构）

| 部分 | 内容与约束 |
| --- | --- |
| 来源 | Rust 解析后固定枚举；不能接受任意 UI 传来的可信来源声明 |
| 接收标识 | 每次真实进程入口分配随机不透明 ID；相同 URL 再次启动仍是独立请求 |
| 待认领数据 | 目标端点、认证身份（整个用户名也视为秘密）、认证材料、接收时间/本地截止时间；仅 Rust 内存，无通用 Serialize/Debug |
| 安全摘要 | 不透明 request handle、固定来源、固定“堡垒机临时连接”类标签、状态与本地过期提示；不含真实主机、用户名、外部标题、原始 URL、argv 或端口 |
| 归属 | 未选择工作区时保持未认领；认领时显式传 workspace_id 并验证存在/可访问，绑定后不可迁移 |
| 动作 | 只能请求一次交互式临时终端；不能携带命令、启动脚本、Task/Flow、SFTP 自动打开、测试连接或额外探测 |
| 消费 | 原子 claim(request_handle, workspace_id) → temporary_target_handle；重复 claim 返回固定状态，不重复连接 |
| 目标 | 临时随机 ID 与 workspace_id；与普通 connection_id 类型/查找路径分开，不能由保存连接接口反查 |

认证变体由真实启动形式决定。当前不能规定“必定密码”、RFC URL 分隔规则、
解码次数、会话文件读取或本地代理连接参数。未知/歧义/重复关键字段与额外执行开关应明确拒绝，
不得静默截断、选择第一个 URI 或把未知字段传给 shell。
请求摘要使用白名单构造，禁止“先序列化真实连接再删密码”。
所有失败返回固定英文稳定错误码，UI 本地化解释；不透传 SSH/server/解析器原始错误文本。

## 投递、时限与清理

以下是建议的本地资源上限，需在 A2/A3 实现与测试中固定；不宣称等于服务器授权有效期：
最多 16 个待认领请求，每个最多 64 KiB 输入，接收后 120 秒过期。
认证/传输建立总上限 30 秒，通道建立上限 15 秒；主机信任等待受独立 120 秒上限约束。
超限拒绝新请求，不挤掉旧请求、不写磁盘、不为了判定有效期发起连接。

| 事件 | 必须满足的结果 |
| --- | --- |
| 冷启动、已有实例、UI 尚未就绪 | 统一 Rust 队列接收；UI 拉取安全摘要。通知仅提示刷新，不能充当唯一存储 |
| UI 重挂载、重复 readiness、单实例转发重投 | 同一接收标识只消费一次；禁止 URL 内容哈希去重造成真实重复启动丢失 |
| 未选工作区 | 不连接；显式选择后 claim。切换工作区不自动认领、不暗改归属 |
| 用户取消/超时 | 原子终止状态；取消正在等待的认证/通道任务，迟到的 transport/channel 立即释放 |
| 主机信任 | 保留 host-key 指纹检查与变更拒绝；临时首次信任策略需与无持久化要求一起实现。必要的指纹/信任选择通过专用安全契约提供，摘要不显示真实端点或认证字段 |
| 认证成功 | 删除不再需要的初始认证副本；保留 transport 所需内存资源；不留再次登录凭证缓存 |
| 关闭标签页 | 清除该目标、句柄、输出缓冲、输入历史与所属 transport/channel |
| 关闭工作区 | 取消/释放该 workspace_id 的请求与目标；其它工作区不受影响 |
| 未归属请求/关闭应用 | 未归属请求按超时或显式取消清除；退出清除所有请求/目标，进程重启不恢复 |
| 断线、授权拒绝、过期 | 进入终态并清理；提示从堡垒机重新发起。无自动重连、凭证复用或静默重试 |
| 代理/辅助进程退出 | 连接失败或断开按终态处理；不推断远端操作完成；未明确归属前不终止 AccessClient 的进程 |

认证材料应使用可清理的 Rust secret 类型，限制复制，并在消费/取消/到期时释放和清零其可控缓冲。
不得承诺能清除 OS 原始 argv、第三方库副本或 AccessClient 自身的记录。
如果 AccessClient 依赖末端进程持续存活，单实例第二进程立即退出可能破坏代理；
该行为必须在 A1 补证后决定是否需要启动器，不能仅靠内存队列认定兼容。

## 持久化、输出和授权边界

临时目标禁止创建普通保存连接、SQLite session/history 行、keychain 记录、导出项、
Cloud Sync mutation/outbox、可恢复活动详情或 Task/Flow 输入。
终端可见输出与本标签页交互输入只保留在有界内存，关闭即清除；
临时标签不提供日志导出、持久命令历史或跨会话恢复。不得自动生成活动记录以保存端点/认证绑定。
主机信任仍校验指纹；临时端点的信任关联应保留在临时目标内存中，
需单独审查现有 host-key store 的持久化入口，不能通过取消检查来避免写入。

不预先 test connection，不登录两次，不发送 OS probe，不自动探测额外 exec/SFTP 通道。
正式连接只建立用户请求的终端通道；A4 手动能力检测按上文单独确认后运行。
后续 Task/Flow 能力仍需 A4 独立证据与后续授权。
