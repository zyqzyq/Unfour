## Flow definitions in the Cloud Sync client

The current client adds Flow definitions to the existing Pro Cloud Sync path:
initial upload, incremental edits, deletion tombstones, remote whole-document
replacement and keep-local/use-remote conflicts. Local mutations retain durable
intent while offline, paused or signed out, under the workspace's existing
durable owner. Upgrade handling captures previously untracked local definitions
and deletions before remote replay can replace them.

**Deployed-server compatibility and real two-device acceptance are NOT VERIFIED.**
Shipping client code and local automated fixtures do not prove a working live
service. No server inspection/deployment or cross-device acceptance is claimed.

| Included in a definition | Excluded from sync |
| --- | --- |
| Name, typed input declarations and ordinary non-secret defaults | Actual run input values, resolved variables, selected run environment and consent |
| Ordered action/control-flow steps and their parameters | Runs, history, status, outputs and execution snapshots |
| Existing API/SSH/Database resource UUID references | Passwords, private keys and device-local credential handles/paths |

Definitions sync as one document with a **64 KiB** compact UTF-8 JSON payload
limit. Conflicts choose one complete local or remote definition; steps are not
merged. Local/unbound definitions keep their existing 1 MiB limit. Rejected
unsafe/oversized saves retain the editor draft; first-upload rejection rolls
back enabling sync. Values are never silently stripped or truncated.

Sensitive inputs must have no default. Put sensitive fields behind runtime
references and configure resource credentials separately on each device.
Validation rejects recognized sensitive literals and device-local material;
arbitrary secrets hidden in SQL, shell text, encoded blobs, metadata or
innocuously named fields cannot be reliably detected. Review definitions before
syncing; this is not sensitive-data Cloud Sync or a general secret detector.

Receiving a definition does not execute it or synthesize missing resources.
References keep their UUIDs, and missing-resource preflight still blocks runs.
Individual Flow deletion retains local run history; deleting the Workspace
purges its local Flow runs. v0.11.0 cannot materialize Flow sync envelopes;
retention/replay and pre-existing local data need real upgrade testing.

See the [user guide](../user/USER_GUIDE.md#flow-definition-cloud-sync-current-main-planned-v0120)
and [client/server contract](../architecture/flow-definition-cloud-sync.md).

## Review and rerun SSH Tasks

- **Use previous parameters** explicitly restores the previous run's context;
  ordinary Run starts with current workspace/active-environment defaults.
- Rerun a successful, failed or cancelled task from completed history or its
  result panel. Each action opens an editable review dialog before execution.
  A rerun uses the current saved task and creates a new run/log; it does not
  resume a failed step or automatically retry an uncertain remote operation.
- Restore safe manual values and re-resolve the original variable sources.
  Sensitive manual values require re-entry. Missing sources/connections or
  stale variable/task/environment metadata block execution; an edited dialog
  survives delayed recall. Legacy runs without context use current defaults.
- Use compact sensitivity locks and independent show/hide controls. Secret
  sources and automatically sensitive names stay locked, including recalled
  provenance and manual edits. Recall and environment changes reset visibility.

Recall context remains local, outside Cloud Sync and Workspace bundles. Mark
opaque manual secrets sensitive; content checks cannot detect every credential.
Packaged Tauri reruns against real external SSH hosts are **NOT VERIFIED**.

## Safer MCP and Database reads

MCP SQL policy and execution share dialect-aware classification. Read-only paths
reject wrapped writes, `SELECT INTO` and assignment PRAGMAs. MCP reads and saved
read-only connections establish and verify a native read-only constraint before
sending user SQL, failing closed if it cannot be established. PostgreSQL/openGauss
and MySQL use read-only transactions; SQLite uses `query_only`.

These constraints protect database state within their supported scope. They do
not isolate file/network functions, independently authorized external writes or
all autonomous/temporary effects. Use a least-privilege database role as well.
SSH diagnostic validation also rejects mutating argument forms previously
accepted as reads; unknown options may now be rejected. MCP health no longer
advertises reserved capabilities that are not implemented tools.

Real external database-engine and production-policy acceptance for this
candidate is **NOT VERIFIED**.

## More reliable results, history and Flow execution

- Keep completed API responses, SQL/row-edit results, SSH/SFTP outcomes and
  session/task handles if later local activity logging fails. Show an explicit
  warning while retaining the result, without retrying the operation. Clean up
  opened SSH sessions if terminal-history persistence fails; that failure still
  reports an error.
- Show API Request snapshots from the built request, with normalized history
  and compatible OpenAPI matching. Require review before reusing lossy history;
  block redaction markers and incomplete explicit Auth. Improve redaction of
  script-generated values in console, assertions, errors and failure paths.
- Default Desktop Flow runs to the active workspace environment, including
  recovery after a failed lookup, while preserving manual selections. Keep
  completed step results in timeout/cancellation races. An in-flight attempt
  without a confirmed result becomes `FLOW_OUTCOME_UNCERTAIN`, without automatic
  retry; remote effects may already have happened. Redact known encoded
  credentials in newly persisted Flow history.
- Distinguish Database result truncation from SQL `LIMIT`, propagate row/byte
  truncation to MCP, and keep row-cap feedback tied to the running query.
- Prevent old SSH Task output from reappearing after history cleanup or
  workspace changes, while preserving other tasks' logs. PROD MCP risk notices
  use the saved counterpart for each independent settings save.

These changes do not promise exactly-once remote execution, rollback of remote
effects, or complete removal of every legacy secret echo from existing history.

## First-use and everyday UI improvements

Flow and Database provide actionable empty/loading/error states and retry paths.
Database offers direct connection setup and returns focus when its dialog closes.
A title-bar MCP entry and Flow/Settings/MCP command-palette actions improve feature
discovery; MCP status can be refreshed in place after a read failure or repair.
Sidebar creation controls are consistent, Flow lists support keyboard navigation,
SSH connection headers stay visible while scrolling, and SSH log copy/export
feedback uses shared English/Chinese messages. Workspace import/export menus
clarify the included resource scope.
