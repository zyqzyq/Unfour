## Open a bastion terminal in Unfour

On Windows, Unfour accepts the Xshell and SecureCRT launch formats observed
with QizhiTech AccessClient in a JumpServer workflow. Use your approved
bastion launch setup to open Unfour as the terminal client. If several
workspaces are available, switch to the intended workspace and confirm.
Unfour opens a temporary SSH tab alongside your saved connections. To reconnect
after a disconnect, launch again from the bastion.

The supported forms are Xshell's `-url <SSH URL> -newtab <label>` and
SecureCRT's `/T /N <label> /SSH2 <host> /P <port> /L <identity> /PASSWORD <credential>`
in that order. Both require an ASCII hostname or IPv4 address and an explicit
port. Xshell accepts a restricted literal `ssh://` URL. Unsupported launch
shapes show a redacted diagnostic.

## Run a Task or API request on the logged-in host

Once you are at the intended host's idle POSIX shell, choose the temporary
session and the logged-in-terminal mode in the SSH Task run dialog or API
route selector. Confirm that shell for each run or send. SSH Tasks in this mode
run command steps. API uses the host's curl for supported HTTP(S) requests
with JSON, text or URL-encoded bodies. Responses are capped at 10 MiB. File
uploads and streaming are outside this mode, and redirects are returned as
responses.

For eligible small requests, run the **Logged-in terminal curl** capability
check on the same shell first. If the echo and recovery checks pass and the
shell still matches, the transfer can use fewer upload round trips. Other
supported requests use the conservative transfer. The response timing view
shows time spent preparing, uploading, running curl and restoring the terminal.

Unfour pauses keyboard input during an operation and preserves a complete
result if terminal recovery fails. If recovery cannot be confirmed, reconnect
from the bastion before using the terminal again. Cancellation can leave the
remote outcome unknown. Check the remote state before retrying.

## Reach private services through SSH

Save and verify a standard SSH jump host in your workspace. Select it in the
API route picker or Redis, PostgreSQL, openGauss or MySQL connection editor.
Enter the service's internal hostname and port so the jump host can resolve
the target. API can inherit an environment default or use a request override.

A live temporary bastion session can also forward traffic for API, Redis,
network SQL or another SSH target in the current window if the server permits
SSH TCP forwarding. The forwarded SSH target has its own login and host key.
TCP forwarding, extra SSH exec channels and reuse of the logged-in shell
have separate capability checks. Direct bastion-specific SFTP and WinSCP
handoff, `rz`/ZMODEM and temporary-session Flow or K3s deployment are outside
this release. Ordinary SSH connections continue to offer SFTP.

## Inspect Redis keys and work with SQL results

In **Database**, create a standalone Redis connection to look up keys, inspect
TTL, and browse Hash, List, Set and sorted-set values. Connections start
read-only. Enable writes on this device for a saved connection to preview
and confirm supported String, Hash and TTL edits or single-key deletion.
Redis checks in Flow and MCP are read-only. Redis Cluster and Sentinel are
outside this workbench's scope.

In SQL **Results**, page, filter and sort the rows already returned by the
query. Copy a cell selection as TSV, or choose the current view across all its
pages or all returned rows for TSV copy or CSV/JSON export. The query's existing
row limit still applies.

## Everyday fixes

- If the selected API tab was a saved request, restarting reopens that request
  from its saved definition. Other tabs, unsaved drafts and previous responses
  are outside recovery.
- Accepting an SSH history suggestion leaves keyboard focus in the terminal.
- MCP masks secret environment and workspace variables in results and
  diagnostics. Authorization and execution use the same workspace and request
  context. Tasks and Flows stop when a command outcome cannot be confirmed.
- The workspace frame and document tabs are more consistent. Ordinary SFTP
  transfers handle destination conflicts more safely, PostgreSQL table exports
  preserve owned-sequence state, and completed updates retain their restart
  prompt across a WebView reload.
