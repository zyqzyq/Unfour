## Import cURL into API Client

Paste a supported cURL command, review its parsed request and masked sensitive
fields, then open an unsaved request tab. Import does not execute shell commands
or send HTTP traffic. Sending later uses the existing Unfour transport and
request semantics.

This is a bounded request importer, not a complete cURL runtime. Unsupported
options/quoting, shell operators or substitutions, local file inputs, multipart
requests and unrepresentable request shapes are rejected. Imported credentials
can exist in the in-memory draft; preview masking is not removal of those values.
See the [supported syntax and verification](../testing/api-curl-import.md).

## Find Database and SSH resources

Database search filters names in the already-loaded tree, preserving ancestor
paths and temporarily expanding matches without fetching more schemas. Clearing
search restores normal expansion. SSH connection search matches name, host,
username and port. It does not filter Tasks or terminal sessions. Search is local
to the Workspace and does not change saved connections.

## Preview remote text files

SFTP offers read-only preview for regular UTF-8 text files up to **1 MiB**, with
explicit copy. Binary data, unsupported encodings, non-regular files and oversized
content are rejected. Reads are bounded and time out after 30 seconds. Preview
content is not persisted in history or shared application caches.

Closing the dialog, disconnecting, or switching Workspace/session discards late
results. Preview is disabled while this client knows of a pending/running transfer
in the same session. Closing a preview does not cancel an already-issued remote
read; it may continue until completion/timeout and contend with a later transfer.
Real server and native desktop acceptance remain separate from fixture tests.

## Keep desktop data and drafts consistent

Open views refresh after committed local writes from MCP, another client or
Cloud Sync. A workspace/domain change clock in SQLite tracks commits; a visible
desktop checks it every two seconds and on activation. Supported edit dialogs
and API/SSH Task/environment editors detect external changes and retain drafts
for review instead of silently overwriting newer saved data.

The upgrade adds a local change-clock table and triggers. It does not add cloud
payload data or execute remote operations on refresh. Saved-record freshness
checks do not make arbitrary remote operations transactional. Validate upgrade
and cross-process behavior against disposable copies of v0.12.0 data.

## Reliability and everyday interaction

- Account failures retain stable diagnostic codes and stages; consumed login
  codes are not exchanged again. A failed startup callback read no longer blocks
  starting a fresh login. Restarted login attempts still require a fresh browser
  flow because pending PKCE state is held in memory.
- Workspace switching keeps list order stable.
- Workspace navigation callbacks remain stable when feature slots refresh,
  avoiding a workbench render loop when returning to Database after Flow runs.
- API shortcuts respect composition, handled events and open overlays. Modified
  tab closes and pending Database edits use confirmation flows.
- Workbench surfaces and editor/data-grid contrast are refined for both themes.
- SSH Task saves update the list and editor immediately. Terminal teardown
  cancels queued animation callbacks to avoid renderer access after disposal.
- SSH session close/cancel and history flushing check Workspace ownership before
  affecting resources. Late failed terminal history reads preserve newer results.
  Internal SQL safety, MCP tool registration and SSH transport responsibilities
  are separated without changing public commands or adding Bastion support.
  See the [hardening record](../testing/release-hardening-2026-11-07.md).

## Compatibility and release status

No dependency upgrade is included. Community/free and Pro continue to share one
application; Pro remains an entitlement. Existing distribution policy remains
Windows x64 NSIS, macOS arm64/x64, and Experimental Linux x64 AppImage on Ubuntu
22.04+. Windows/macOS OS signing and Apple notarization are not added.

Bastion/jump-host routing and interactive MFA authentication are **not included**
in v0.13.0. They require a separate SSH transport and authentication effort.

The [preparation report](../testing/v0.13.0-release-preparation-2026-11-07.md)
and [RC report](../testing/v0.13.0-rc-final-verification-2026-11-07.md) retain
their original scopes. The subsequent Standard Release published 13 GitHub assets
and promoted both Stable manifests to 0.13.0. Publication does not turn missing
native/live-service checks into PASS. Microsoft Store submission is separate.
