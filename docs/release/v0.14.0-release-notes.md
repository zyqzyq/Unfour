# Unfour v0.14.0 — draft release notes

Status: **NOT RELEASED / RC NOT STARTED**. Prepared on 2026-11-09
(Asia/Shanghai). The latest published Standard stable release remains v0.13.0.
The reviewed feature baseline is `d3b35b91bd0e888c60719010a34babd78a6ce543`;
the final candidate must also include this preparation's version/documentation
changes. See the [verification record](../testing/v0.14.0-release-preparation-2026-11-09.md)
and [current release checklist](release-checklist.md#v0140-preparation-status).

## A clearer C2 workbench

The selected C2 design now brings consistent surfaces, navigation, focus states
and compact layouts to API Client, Database, SSH/SFTP/Tasks, Flow and Settings.
Light, dark and system themes remain available. API tabs and narrow layouts are
refined; dragging navigation or layout controls avoids accidental text selection,
while editors and output retain selection support.

Layout dimensions are normalized when loaded, dragged and saved, fixing fractional
pixel values that could fail the desktop's integer-size contract. Actual native
scaling, clipboard and restart acceptance are recorded separately from browser tests.

## More reliable everyday operations

- API failures and Retry remain visible in Request, Tests and Console. Retry uses
  the current edited draft. Database Messages now displays command-level connection
  and execution failures; successful execution clears obsolete errors.
- SSH Task output stops following when you scroll up to read. Returning from another
  module preserves that reading position; the follow control resumes live output.
- Unsaved Flow drafts, including invalid JSON and drafts hidden behind another module,
  receive a Cancel / Discard confirmation before changing, creating or deleting a
  workspace. Cancel is the default. Pending workspace creation/deletion cannot be
  dismissed or submitted twice.
- Environment changes are serialized per workspace. Send, Retry and keyboard send
  are blocked while switching; after the queue finishes, execution uses the last
  successful activation. Failed activation shows an error and retains the previously
  confirmed environment. Different workspaces keep independent queues.

Leave protection does not add autosave, save-and-switch, window-close/crash recovery
or draft persistence. Once discarding is explicitly accepted, a failed workspace
activation does not guarantee recovery of the discarded Flow draft. Environment
ordering covers this UI's requests, not a cross-process lock against MCP changes.

## New MCP resource management

The registry grows from **72 to 87 tools**, adding 15 tools:

- Create and rename workspaces. Creation keeps the active workspace unchanged and
  inherits the authorizing workspace's environment and MCP policy; it cannot supply
  a policy override.
- List/create/rename/move/reorder/delete API folders; move and duplicate requests.
  Folder moves stay inside a collection; request moves stay inside a workspace.
  Recursive deletion uses a revision snapshot and transaction-time conflict check.
- List/get/save/delete Saved SQL. Update/delete requires the expected revision.
  Metadata-only updates preserve the original SQL. Reads return masked diagnostics,
  which must not be treated as original SQL to save or execute. These tools manage
  records; they do not execute the SQL.
- Discover database catalogs through the configured database driver and connection.

Workspace ownership, environment-aware MCP policy and confirmation remain in force.
Clients must start the updated MCP binary to see the new registry. See
[MCP tool contracts](../mcp/tools.md) for names, arguments and driver-specific behavior.

## Fixes to existing MCP SSH file operations

`unfour.ssh.write_file` and `unfour.ssh.patch_file` already existed in v0.13.0.
This release repairs their execution and safety behavior; they are **not new tools**.

- Remote execution needs an `ssh-native` build and a saved, authenticatable SSH
  connection. Only regular files are supported; observed symlinks/directories are
  rejected. Write uses SFTP without a terminal session, local content staging or
  remote Python. Overwriting an existing target requires
  `posix-rename@openssh.com` version 1; unsupported servers fail before replacement,
  with no backup-move fallback.
- Patch needs remote **`python3` through a POSIX-compatible SSH command shell**.
  Default Windows cmd/PowerShell SSH shells are not covered by this helper.
  A fixed helper receives UTF-8 JSON
  over stdin, handles matching explicitly, and replaces through a sibling temporary
  file with a metadata conflict check.
- Write content or combined patch search/replacement is limited to **4 MiB UTF-8
  bytes**. Patch target and result files are limited to **16 MiB**.
- New files use mode `0600`; replacement preserves basic owner/group/mode.
  Extended ACLs/attributes and hard-link identity are not preserved.
- Append is not atomic and can partially complete. Timeout, cancellation or a lost
  commit reply does not prove rollback. Read back the destination before retrying;
  cleanup after disconnect is best effort and temporary siblings may remain.
  No guarantee is made against every external writer or server power loss.

## Compatibility and validation boundary

The release remains one application for Community/free and Pro. Distribution stays
Windows x64 NSIS, macOS arm64/x64, and Experimental Linux x64 AppImage with Ubuntu
22.04+ as the baseline. Updater signatures do not imply OS code signing or macOS
notarization; Store submission is separate. No new storage migration is introduced
after v0.13.0. The existing `sha2` dependency is now used directly by MCP for
content-bound confirmations; no dependency version upgrade is included.

JumpServer/AccessClient integration, website updates and further large refactoring
are deferred. Local checks, browser fixtures, protocol fixtures, native desktop
acceptance and real-service acceptance are separate evidence layers. Unrun cases
remain **NOT VERIFIED**; neither earlier releases nor an older SHA's RC prove this
candidate. No formal tag, GitHub Release or public Stable manifests are changed
by this preparation.
