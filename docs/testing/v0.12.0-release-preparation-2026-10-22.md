## Release-process contract

- Versions remain **`0.12.0` without an RC suffix** across Cargo, Cargo.lock,
  package manifests and Tauri. Community/free and Pro share the same build;
  Pro is an entitlement. The candidate does not require creating `v0.12.0`.
- [Standard Release Candidate](../../.github/workflows/release-candidate.yml)
  is manual and has `contents: read`. Its identity job validates the Standard
  Stable contract and pins the selected `ref` to a commit. The
  [shared verify/build workflow](../../.github/workflows/reusable-standard-build.yml)
  checks that exact commit and uses `stable` / `standard`.
- The reusable verify job must still pass lint, frontend tests, release tests,
  aggregate checks (including versions, secret/migration/large-file/token
  guards and frontend/Rust checks), SSH-native check, Rust tests and browser
  E2E on the selected SHA. CI #319 does not replace this job.
- Four native builds follow verify: Windows x64 NSIS, macOS arm64/x64 DMG plus
  updater archives, and Linux x64 AppImage. Linux uses **`ubuntu-22.04`** and
  its runner-specific Rust cache key. The build job binds **`production`** for
  the updater signing key and fails if the key is absent. Current Environment
  secrets/approvals were not inspected by this closeout; workflow execution
  must establish their availability without exposing secret values.
- RC uploads four `release-candidate-*` Actions artifacts with canonical files
  and updater `.sig` files. It does not aggregate `SHA256SUMS.txt`, `latest.json`
  or `downloads.json`; record downloaded-file SHA-256 values for acceptance.
  Updater signatures do not imply Windows/macOS OS signing or notarization.
- RC has no tag/Release creation, R2 publication, Stable manifest promotion or
  MSIX/Store publication path. Inspect the actual run for this isolation.
  Use isolated candidate updater fixtures for update/signature rejection tests,
  leaving public Stable manifests unchanged.
- A later separately authorized [Standard Release](../../.github/workflows/release.yml)
  resolves an existing immutable `vX.Y.Z` tag and rebuilds the accepted source
  through the same core. It does not promote RC bytes automatically. Its publish
  job finalizes checksums/manifests, verifies immutable R2 bytes, creates the
  GitHub Release and promotes downloads before updater. No such publication is
  authorized or performed here. See the [shared procedure](../release/release-checklist.md#release-candidate).
