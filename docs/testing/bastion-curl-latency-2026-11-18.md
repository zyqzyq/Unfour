# 已登录堡垒机终端 curl 的耗时与验收

## 小请求优化（基于 009e7c5b）

选模式、切换页面和卸载 API 界面均不申请租约。实际发送时占用原来的 PTY。请求持有独占权直到匹配的 RESTORED。恢复失败保留完整响应、告警和输入隔离。沿用当前分支的取消管理、脱敏与不自动重发语义。

### 协议与启用条件

- V4 将随机关联 ID 随固定启动命令传入，省去 STARTUP 后提交 session ID、READY 后提交 operation ID 的两次单独发令。每次重新检查工具、回显保护与严格 curl CLI 兼容性。匹配 READY 之后才发送请求值，上传数据只含本次配置。
- 固定代码分两段。含 LF 的启动行为 1,696 B，收到 LOAD 后的第二行为 1,387 B（冷保守）、1,644 B（快速候选）、1,471 B（检测）或 1,457 B（首 @），另有 2 B 起始行。最长单次发送为 1,696 B，底层每次写入最多 512 B。PULSE 后的一字节换行给截断行提供边界。长度不足时只重送固定代码，逐段最多 240 B。接收器先校验固定代码 SHA-256，缺少工具时由客户端逐字节核对公开代码回显。256 B 故障注入发生在 LOAD 之后，最初启动行仍需完整交付。
- 保守路径逐行核对完整编码内容，再提交 E。130 B JSON 生成 413 B 配置，完整输入帧 566 B，3 个数据 ACK 和 1 个结束确认。保留八进制回退、原有 512 KiB 请求上限、10 MiB 响应上限及 HEAD 行为。
- curl 能力检测连续发送一次 720 B 合成载荷，完整编码帧为 1,041 B。必须逐字节回读并成功恢复才记住档位。候选请求重新核对 tty、主机名及父 shell PID 的摘要。未检测、上下文改变、窄中继、缺摘要、超出总帧上限或正文首字节为 @ 时走保守路径。手工输入、Task、重新检测、断线、协议或恢复失败使资格失效。
- 快速路径连续发送 B 行及 F 结束行。接收器核对行数、实际长度和顺序拼接的全部编码数据 SHA-256，成功即执行，只等一次结束确认。摘要包含方法、URL、头、正文和执行参数。130 B JSON 占 631 B；带长鉴权头的 GET 为 1,917 B，自动走保守路径。
- 保留正常 Q → RESTORED 的一次同步。完整输出与取消相遇时，子 shell 仍持有终端，迟到的 Ctrl-C 不会击中父 shell。恢复有独立 3 秒预算。确认接管前不会向父终端发中断。被占用时拒绝的键入不会在释放后重放。

### 请求、传输和耗时字段

- 每次从子 shell 验证解码器能输出已知字节并正常退出。通过后每个 D 行携带最多 180 个原始字节的 base64，只有编码器时使用原有 48 字节八进制。两种编码均限制为线上 242 字节（含行首与换行）。一次只发一行，校验操作标识、序号、编码长度及完整回显，再发送下一行。最终行继续核对总行数与总编码长度。
- 固定 bootstrap 长度由 1,721 B 降到 1,697 B。选择更紧凑的编码已能减少串行等待，没有启用多行窗口。原有长输入丢失和中继容量仍决定哪些优化适合现场。
- curl 7.29 的普通 JSON 从三次无网络 curl 预检减为一次。共用的严格 CLI 控制参数同时用于预检和业务传输，`--version` 放在检查参数最后。URL、凭据及正文经已验证的 shell 内建 printf 和管道传入 curl 配置，不写远端临时正文文件。首字节为 `@` 的正文单独验证 `--data-raw`，7.29 明确拒绝并保持零次业务 HTTP。
- 准备覆盖启动至 ACCEPT；输入覆盖数据发送至结束确认。远端执行与回传覆盖结束确认后等待、预检、HTTP、输出读取及解码。curl 的 `time_starttransfer` 和 `time_total` 从目标机本次 HTTP 传输开始累计；ACK 等待包含在输入时间内，首字节包含在 curl 总耗时内，各列不能直接相加。
- 阶段数字随本次完整响应返回，包括 HTTP 错误响应。历史仍记录原有总时长；操作未取得完整响应时，使用原有阶段错误码。
