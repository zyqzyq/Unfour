## Changes and boundaries

### CI / generated assets

The checker exempts a file under `apps/desktop/public/monaco/vs/` only when
the installed editor version equals the exact desktop dependency pin and its
bytes equal the corresponding file in that dependency's `min/vs` distribution.
Missing, changed, unknown, and version-mismatched files remain subject to the
normal source thresholds. No baseline or threshold was relaxed. Daily CI now
copies Monaco and runs this guard; the checker regressions also join the
shared release contract suite.

The offline-editor smoke test had a stale accessible-name locator (`API`);
it now uses the current `API Client` button. The first full browser run failed
that locator and timed out during a Flow screenshot while eleven browser
workers competed with compilation. A complete four-worker rerun passed all
sixteen tests without changing assertions, timeouts, or the checked behavior.

### Startup history repair

The empty legacy-history repair batch held `BEGIN IMMEDIATE` until
`Transaction::drop` queued a rollback on SQLx's worker. Subsequent startup could
read on another pooled connection and attempt to promote a deferred transaction
while the earlier RESERVED lock was still pending. The repair now explicitly
awaits rollback before returning. A file-backed two-pool regression exercises
the empty repair followed by a deferred read/write startup transaction.
This explains the common path in the two Actions failures; their Linux rerun
on the new commits remains required.

The first Windows workspace run also exposed an MCP test-fixture cleanup
failure (`ERROR_SHARING_VIOLATION`) after rollback assertions. Its setup/read
helpers now explicitly close SQLite pools before deleting the temporary
directory. This is test lifecycle cleanup; adapter policy and assertions remain
unchanged.

### OpenAPI history association

Neither `ApiRequestInput` nor `api_history` carries a saved-request ID. The
execution diagnostic `request_id` is a new per-execution ID and is not a usable
saved-request association. No persisted ID or schema was invented.

The SQL prefilter retains Workspace, active collection membership, and method
scoping, leaving lossy payload comparisons to the shared history redaction
projection. Both local requests and histories, including old plaintext rows,
are normalized through that existing projection. Matching retains name, method,
URL, headers, query, and public body content, including JSON semantic equality
and encoded redaction-marker compatibility. Selected response examples are
sanitized before export. Stable saved-request IDs attach the results to the
sanitized document copies; raw matching copies are internal and `serde(skip)`.

Service-level database regressions cover ordinary and sensitive requests,
all five protected header names, URL/query/body fields, JSON and raw form bodies,
legacy rows before/after repair, public-field mismatches, Workspace isolation,
and unchanged saved definitions. Existing export tests also pass.

An existing metadata-free, redacted history cannot distinguish two definitions
whose name, method, and entire public request projection are identical but whose
secrets differ. This minimal compatibility fix does not reconstruct lost secret
values or introduce a persisted fingerprint. Requests transformed by scripts or
variable resolution retain the existing snapshot-matching limitation.

RC re-review found that the matching projection omitted Auth-panel fields
materialized during Send. The [2026-10-10 Auth history follow-up](v0.11.0-rc-openapi-auth-history-2026-10-10.md)
records that correction, its fresh regression evidence, and the remaining
strict snapshot-matching limits. This earlier record does not verify that fix.

### Desktop credential reveal

Reveal reuses the existing per-database OS credential lifecycle lock, also used
by same-reference rotation/deletion. SQLite is not held during Keychain I/O.
The initial lookup checks the live Workspace, live SSH/Database aggregate,
requested reference, and connection revision. After I/O a short
`BEGIN IMMEDIATE` validates the same membership and revision on a fresh snapshot;
rollback completes before the secret returns. Revision rejects replace/restore
ABA races. Failed validation, SQL errors, backend errors, and cancellation return
no secret; temporary loaded values use the existing `zeroize` dependency.

Two-pool tests pause the credential read and exercise unrelated writes, connection
replacement/deletion, Workspace deletion, subtype removal, ABA, GC, same-reference
rotation/deletion, backend/SQL errors, invalid scope/type/reference, and cancellation.
Credential lifecycle operations can wait behind a pending OS read; unrelated
SQLite writers and deletion/GC remain free to progress. No MCP dispatch/tool or
frontend contract gains plaintext credential access.

No new dependency, secret storage architecture, SQLite field encryption,
sensitive Cloud Sync behavior, migration, or V1/V2 backup format was introduced.

## RC decision

checks pass. This is preparation evidence, not a verified v0.11.0 RC artifact.

later set the intended version and run the existing Standard RC workflow for
Windows x64, macOS arm64/x64, and Linux x64. Record native installer/updater
and OS credential-store behavior against those exact artifacts before release.
No historical v0.10.0 Actions success substitutes for that evidence.
