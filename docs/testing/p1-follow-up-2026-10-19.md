## F-02 — SSH read-only bypass — repaired

- Root cause: MCP and the SSH engine maintained different command classifiers, and both treated several mixed-purpose utilities as read-only regardless of arguments.
- Reproduction: `ip link set eth0 down`, `mount -o remount,rw /`, `hostname audit-name`, or `date -s 2030-01-01` passed the old validator. With sufficient remote account privileges, `read_only` or production `auto` automation could change host state. The new negative regression failed on the original code with `accepted ip link set eth0 down`; no destructive command was executed remotely.
- Repair: `crates/ssh-engine/src/diagnostics.rs:65` owns the shared validator, re-exported through CommandBus for MCP. `crates/unfour-mcp/src/tools/ssh_risk.rs` delegates to it. `crates/ssh-engine/src/diagnostic_arguments.rs:4` explicitly accepts conservative read forms for IP/network, hostname, date, mount and journal commands; unknown/mutating flags and abbreviations fail closed. `systemctl` requires its read verb first, preventing value-taking global flags from hiding a write verb. `kubectl cluster-info` cannot select `dump` and its file-output options.
- Regression coverage includes socket destruction/dump flags, interface changes, batch files, numeric date setting, long-option abbreviations, global-argument confusion, safe read forms, and engine rejection before connecting. MCP tests enforce both explicit read-only and production-auto boundaries while retaining ordinary full-access execution policy.
- Compatibility: no stored command/task rewrite. Some previously accepted diagnostic forms, including unrecognized safe options, are deliberately rejected. Supported examples include `ip addr show`, `ip -4 route show`, `ip link show dev eth0`, `hostname -f`, `date -u +%FT%TZ`, `mount -l`, `ifconfig eth0`, `ss -tulpn`, and `journalctl --unit=nginx -n 10 --no-pager`. Broader commands must use the existing authorized exec route; read-only policy does not grant that route.

## F-03 — completed effects reported as failures — repaired

- Root cause: CommandBus propagated local activity-store errors after target SQL committed or SSH task execution started. Callers lost the successful result or run handle and could repeat the effect.
- Reproduction: a disposable target SQLite database receives an INSERT while a trigger in the separate application database rejects activity writes. Before repair, the independent target row count was 1 but CommandBus returned `Err(Database(...audit sink unavailable...))`. The new regression failed at the successful-outcome assertion on original code.
- Repair: `crates/unfour-command-bus/src/database_commands.rs:191` preserves query and row-mutation results; `crates/unfour-command-bus/src/ssh_commands.rs:447` preserves task-start and cancellation handles. `crates/unfour-command-bus/src/completion_activity.rs:6` catches only the subsequent activity-recording error, returns stable `ACTIVITY_RECORD_FAILED`, and emits a diagnostic containing the error kind without raw SQL, commands, storage errors or secrets. Execution errors and pre-execution confirmation/guard failures still propagate normally; no operation is retried to repair its log.
- Rust/TypeScript response contracts add optional `warnings` to database results and SSH task runs. Absent fields default to empty; empty fields are omitted by Rust serialization. SSH warnings are response-only, not added to persisted task-run columns. Older saved/JSON results remain readable; no backfill or database migration occurs.
- Desktop hooks keep the result/run selection or clear successfully applied pending row edits, then show a shared, localized feedback message. MCP SQL output schemas and SSH projections preserve warnings and successful outcomes. Flow retains SQL warnings and carries the initial SSH warning through completion/failure diagnostics, even though subsequent task-history reads do not contain this transient response field.
- Regressions inject actual SQLite activity failures across query, row mutation and Flow, assert committed row counts and a single Flow attempt, and keep real SQL failures/confirmation rejection intact. A local native SSH server holds a channel open for deterministic cancellation, then completes a second Flow command; tests assert returned handles, warnings, one execution per command, and legacy response deserialization. Caller tests cover desktop result retention, pending-edit removal, cancellation handles and MCP warning serialization.

## F-03 session and trust completion — closed

The earlier repair covered SQL, SSH exec/diagnostic, SFTP, and SSH task start/cancel. These Command Bus paths still turned a later activity-store failure into a command error after the effect existed:

- `connect_ssh_session` dropped the live session id.
- `close_ssh_session` reported a closed session as a close failure.
- `clear_ssh_task_runs`, `reset_ssh_host_fingerprint`, and `import_ssh_known_hosts` reported completed local deletes or imports as failures.

They now use `record_completion_activity` and return `ACTIVITY_RECORD_FAILED` on the successful result. Desktop connect, close, host-key reset, and task-history clear show the existing activity warning. MCP task-history clear keeps the deleted counts and the warning.

Intentionally unchanged:

- `test_ssh_connection` and `export_ssh_log` still fail if the audit write fails. The test probe is already closed, and log export only reads history; retry does not repeat a committed workspace mutation.
- Connection and task save/delete/reorder still record activity inside the business transaction, so an activity failure rolls the mutation back.
- SSH engine terminal-history insert/update errors still fail connect or close. They are not activity-log warnings, and a failed history write is not reported as success.

Compatibility: `warnings` is optional and omitted when empty. Session warnings are not stored in `ssh_terminal_history`. `ssh_host_key_reset` now returns `{ "deleted": bool, "warnings"?: string[] }` instead of a JSON boolean. No schema, Cloud Sync, or permission change.

Verification for this pass: command-bus fault injection without native SSH, one native loopback session test, MCP clear projection, affected Vitest files, `cargo check --workspace --all-targets --features ssh-native`, desktop `tsc`, ESLint on changed TypeScript, and the frontend production build. F-03 can be closed for the audited SSH Command Bus paths above.
