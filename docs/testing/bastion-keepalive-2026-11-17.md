# 堡垒机临时会话保活现场测试

## 现场反馈与定位

用户确认 Xshell 开启 60 秒保活，没有开启空闲发送字符串；VDI 长时间无操作退出后，
重新进入时原 Unfour 窗口仍在，只有 SSH 断开。代码检查发现临时传输关闭了所有 SSH
保活，且旧安全守卫会在任何重新协商时结束连接。锁定 russh 的默认重新协商时间为
3600 秒，在后续收发时触发。这两个缺口均影响长连接，但没有现场关闭原因，不能
认定它们是每次断线的唯一原因。

## 本轮行为

- 临时传输使用 SSH 协议保活：空闲 60 秒后发送，最多容忍 3 次未回应；任意收到的
  SSH 数据都会重置失活计数。完全没有接收数据时，第 4 个周期判超时，约 4 分钟。
- 心跳由 Rust 传输维护，页面隐藏和 VDI 桌面断开不依赖前端计时器；前提是虚拟机、
  进程和网络仍在运行。虚拟机暂停/休眠或网络中断时不能承诺维持连接。
- 心跳不写 PTY，不发送回车、字符串或业务命令；不会干扰终端 Task 或 API curl。
- 保留传输/认证各 30 秒、PTY 启动 15 秒上限，不恢复普通 SSH 的 3 秒探测策略。
- 保留正常 rekey，逐次校验本轮主机密钥并匹配原连接指纹；密钥不符立即拒绝。
- 断开显示固定错误分类；不自动重新登录、重放堡垒机票据或重跑 Task/POST。

| 固定码 | 含义 |
| --- | --- |
| `TEMPORARY_KEEPALIVE_TIMEOUT` | 未在允许的保活周期内收到 SSH 数据 |
| `TEMPORARY_REMOTE_DISCONNECTED` | 远端主动结束 SSH 传输，具体远端描述不展示 |
| `TEMPORARY_TRANSPORT_CLOSED` | SSH 传输已结束，不能据此猜测网络或授权根因 |
| `TEMPORARY_REMOTE_SHELL_CLOSED` | 远端终端通道结束 |

原主机密钥不匹配与无法验证重新协商的安全码仍优先保留。

## 现场验证

1. 关闭旧版并替换本轮 `unfour.exe`，通过原堡垒机入口重新登录目标机。
2. 确认终端可输入，然后切到 API 页面；不运行定时输出命令，不用回车维持活跃。
3. 第一轮保持 VDI 在线空闲超过原来常见断线时长，至少跨过一小时重新协商周期。
4. 第二轮正常断开 VDI 桌面客户端，重新进入后检查原应用、原终端是否仍在。记录
   断开/返回时间、是否虚拟机暂停或网络切换，以及是否需要再次授权登录。
5. 返回终端执行一个获准的只读命令；再运行已登录终端 SSH Task 和 JSON POST，确认
   保活和重新协商没有插入输入、制造额外登录或破坏终端恢复。
6. 若仍掉线，记录界面断线提示（有错误码时一并记录）、发生时间、空闲时长和 VDI 状态。不要带回真实票据、
   用户名、客户地址或原始终端日志；不得直接重发结果不确定的 POST。

客户端心跳不能替代堡垒机授权续期，也不保证绕过服务端强制会话时长。
