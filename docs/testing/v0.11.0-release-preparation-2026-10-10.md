## RC build dispatch and follow-up

After a separately authorized push makes this preparation commit reachable on
remote `main`, open **Actions → Standard Release Candidate → Run workflow**.
Select workflow branch `main` and set input `ref` to the reviewed full commit SHA
(preferred over a moving `main`). CLI equivalent, for the operator to run later:

```powershell
$candidateCommit = git rev-parse HEAD
gh workflow run release-candidate.yml --repo zyqzyq/Unfour --ref main -f "ref=$candidateCommit"
```

The RC workflow validates `v0.11.0`, pins that commit, then calls the existing
reusable Standard verify/build workflow. Its verify job reruns the project's full
gates on Linux. The build job uses the `production` Environment updater key and
produces exactly these Actions artifacts:

- `release-candidate-x86_64-pc-windows-msvc`: canonical NSIS `.exe` + `.sig`.
- `release-candidate-aarch64-apple-darwin`: arm64 DMG + `.app.tar.gz` + `.sig`.
- `release-candidate-x86_64-apple-darwin`: x64 DMG + `.app.tar.gz` + `.sig`.
- `release-candidate-x86_64-unknown-linux-gnu`: x64 AppImage + `.sig`, built on
  `ubuntu-22.04` with the runner-specific Rust cache.

Record the resolved SHA/run and artifact checksums; inspect canonical `0.11.0`
filenames, architecture and non-empty updater signatures. Then execute the manual
checklist above against those downloaded artifacts. Confirm the RC created no
