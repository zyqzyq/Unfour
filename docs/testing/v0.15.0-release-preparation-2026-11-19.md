### Small terminal-curl requests

The fast transfer requires a successful curl capability check that verifies
exact input and restoration in the same live shell. Each send still checks
required curl options and shell context. The config must fit the tested
720-byte sample and the encoded frame limit. SHA-256 verifies the upload.
Missing or invalidated qualification, a narrow relay, an oversized frame
or a body that begins with `@` uses the conservative path when compatible.
Both paths keep manual input isolated until restoration is confirmed.

In the prior Windows x64 test using Git for Windows POSIX PTY, curl 8.18.0
and a local HTTP fixture with 200 ms server delay, a 130-byte JSON body under
**680 ms injected RTT** reached terminal restoration in a median 10.063 s
on the previous conservative implementation, 6.734 s with the new
conservative transfer and 5.078 s with the qualified fast transfer
(three samples each). At zero injected RTT the measured fast path was
slower than the baseline. Actual customer latency, HTTPS and relay capacity
remain **NOT VERIFIED**. [Measurement method and results](bastion-curl-latency-2026-11-18.md)
