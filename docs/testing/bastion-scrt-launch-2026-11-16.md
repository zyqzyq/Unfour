# AccessClient scrt 入口离线测试包

本包在此前安全启动诊断的基础上，增加客户 AccessClient 已报告的 SecureCRT (`scrt`)
外层参数兼容，保留 Xshell 入口。无需安装 SecureCRT，不改 AccessClient、网页协议
关联或 Xshell 程序。用户自行在内网完成实际链路验证。

## 现场依据与支持范围

现场脱敏弹窗确认 11 个参数及顺序，下面的占位符代表预期语义，不含真实值：

```text
/T /N <标签> /SSH2 <连接地址> /P <端口> /L <用户名> /PASSWORD <凭据>
```

诊断器规范化了开关大小写，解析接受 ASCII 大小写等价的开关。标签校验后丢弃。
连接地址接受 ASCII 域名或标准 IPv4，端口为 1–65535 且无前导零。用户名和凭据非空，
按独立参数原样传递，包括空格、Unicode、`@`、`:`、`%` 等字面字符，不做 URL 解码。
所有字段禁止控制字符及 `|`，合计最多 64 KiB，标签不能全空白。

只接受这套固定顺序，不支持脚本、会话文件、额外开关和任意参数重排。保留原有
Xshell `-url <SSH URL> -newtab <标签>` 格式及其原有校验。两种入口都进入原有 Rust
临时会话队列，仍需主机指纹确认，凭据不进入前端、普通连接、历史、导出或云同步。
不支持的格式继续显示脱敏启动诊断。

## 内网测试步骤

1. 退出旧测试程序，备份旧目录，将新包解压覆盖原测试目录。保持 AccessClient 的
   scrt 已选择的 `unfour.exe` 路径，避免仍然启动旧诊断包。
2. 从网页选择 **scrt** 发起一次授权的测试连接。单工作区应自动切到 SSH；多个工作区
   仍在目标工作区认领。遇到未知主机指纹时，核对后仅本次信任。
3. 确认终端连接到预期资产，左侧 SSH 连接列表仍存在。手工输入一条允许的无害命令，
   确认输入和输出正常。不要把终端连接成功记录为 Task/Flow 或 SFTP 验收通过。
4. 保持 Unfour 开启，再从网页发起一次新的授权测试连接，检查热启动、正确的新标签、
   原会话保持及关闭单个临时标签的行为。不要复用旧票据测试第二次登录。
5. 网页选择 **xshell** 时，应继续使用你原来的 Xshell 路径映射；本包不会改它。
6. 若再次出现启动诊断，在资源管理器地址栏输入 `%TEMP%\Unfour-launch-diagnostics`，
   只返回本次最新的 `launch-*.txt` 或脱敏弹窗截图。不要发送原始命令行或凭据。
   若已进入 SSH 但连接失败，记录阶段和固定错误码，截图前隐藏客户资产信息。

普通 ZIP 包含 `unfour.exe`、MCP sidecar、本机回显服务、说明、构建元数据和 SHA-256。
原测试包已能启动的机器使用普通 ZIP 即可。`-full.zip` 额外附带原来的 WebView2 和
VC x64 离线安装程序；两种包的主程序相同。

  OAuth 委派、scrt 字段映射与字面值保留、异常/额外参数拒绝、非法 Unicode、
  请求队列独立性和脱敏输出。

  原生 SSH 桌面程序；构建元数据导出正常。Rust 格式、Node 语法和 diff 检查通过。
- PASS：实际测试包分别运行 `verify-windows-package.mjs <包目录> scrt` 与 `xshell`。
  每轮完成该入口冷启动、同入口热启动、另一入口热启动，共 6 次真实回环 SSH 认证、
  PTY 建立、尺寸同步、指纹确认、回显和关闭。自动进入 SSH 与左侧连接列表正常。
- PASS：冷态额外执行参数、热态追加 `/SCRIPT` 均被拒绝并生成脱敏报告，热态拒绝
  不影响原有终端，未产生额外认证。每轮的连接/信任/历史/任务/SSH 活动/outbox 记录
  为零，隔离数据、日志、WebView 和诊断目录中未发现测试凭据。
- PASS（用户现场反馈）：用户使用本次 scrt 兼容包，从现有堡垒机链路登录成功。
  这是用户报告的现场结果，本轮未直接连接客户环境。先前提供的诊断弹窗截图也确认了
  窗口可读、11 个参数的结构和脱敏报告位置。
- NOT VERIFIED：现场冷/热启动的逐项记录、正确资产独立核对、凭据有效期、代理生命周期、
